## Private interface and lifetime

`McpLease`, `ReadyServer` and public `status()` shapes are unchanged. `McpManager` retains `pool` as the one **current** entry per ID, plus a private `entries` set containing current and retired generations and `leaseEntries` mapping each lease ID to its exact held entries. `PooledEntry.configKey` compares only effective connection settings in memory: transport kind, command/args/cwd or URL, sorted resolved env/headers, missing-secret names and credential-error state. The label is deliberately excluded; a reused connection supplies the new label in the lease. Resolved credentials and comparison keys are never persisted or logged. Config snapshots are copied before constructing a connection to protect already-issued leases from a mutable registry object. A change installs a new current entry while old leases retain their old connection; A→B→A constructs three generations, not a resurrection of A. Identical concurrent acquisitions share a connecting promise. Only last-holder release closes its own entry, deleting `pool[id]` only if it still points to that entry. `closeEntry` deduplicates overlapping teardown and waits for pending connect; `destroyAll` closes current plus retired generations. Disabled/removed servers are absent from new leases while existing snapshots work.

`status()` still reports one row for the current generation of each ID. A previous not-ready entry does not poison a changed-config acquisition; missing-secret/credential-error placeholders remain resource-free. Unchanged errors are not retried on every acquire. Exclusion logging retains ID/state but omits provider error text, which might echo a resolved secret; close failure logging likewise avoids potentially secret-bearing error messages. Full error remains available through the existing public status response, which is not logging or persistence.

## D1 review correction — release/destroyAll teardown race

Before correction, `releaseLease` removed a generation from `entries` **before** awaiting its `conn.close()`. A concurrent `destroyAll()` therefore saw no closing generation and could return while its transport was still open. The fix keeps the generation in `entries` through the close await, removes the current `pool` mapping **before** that await as before, and removes `entries` in `finally`. `destroyAll` likewise retains its snapshot's entries until their close settles, so repeated/concurrent teardown awaits the same deduplicated `closeEntry` promise. Acquisition after teardown starts still gets a fresh entry. No public interface changed.

Deterministic deferred-close regressions were added to `youcoded/desktop/tests/mcp-manager.test.ts` (one released generation plus two concurrent destroyAll calls; one retiring generation with another current and a later new acquisition). The tests wait on a close-start signal and an event-loop turn, not a sleep; each releases its deferred close in `finally`.
