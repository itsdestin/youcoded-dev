# Welcome Back / Close-Warning UX Review 2 — 2026-09-24

Findings from clicking through the "Welcome back" (crash-recovery) screen and the
close-window warning, as a first-time user. Numbered most important first.

- U1 accepted — the list must scroll when a row's tag/note sheet opens; no row may hide behind the footer. Finding: Expected the fourth session in the Welcome Back list to still be selectable after I opened its neighbor's tag editor / expected the list to scroll if content got taller — instead, clicking the tag icon ("Organize") on any session but the last one expands an inline tag/note editor that pushes the sessions below it down, but the list panel does not grow or scroll. The last session card ends up hidden behind the fixed "Resume all 4" / "Start fresh" buttons at the bottom, with no scrollbar to reach it. While the editor is open you cannot see, check/uncheck, preview, or resume that hidden session. — Welcome Back screen — `scratch/ux2/06-rename/midnight/organize-click.png`, `scratch/ux2/07-organize-scroll/midnight/organize-then-scroll.png`

- U2 accepted — after a partial Resume, say how many reopened and why the rest stayed. Finding: Expected "Resume all 4" to either resume everything the same way, or clearly explain what happened — instead it silently resumed 3 of the 4 sessions in the background (they appeared as new tabs behind the dialog) while the Welcome Back panel stayed open, quietly relabeled itself from "These sessions were open when YouCoded closed" to "This session was open when YouCoded closed" (plural to singular, easy to miss), and showed only the 1 remaining session (the one whose old model isn't available) with a new "Resume 1" button. Nothing on screen says "3 of 4 resumed — this one needs a model." A user could easily think the click did nothing, or worry the other 3 were lost. — Welcome Back screen — `scratch/ux2/10-resumeall/midnight/resume-all-click.png`

- U3 rejected — the workbench preview is a fixed fake transcript; the real app reads each conversation. Finding: Expected clicking a different session in the list to show that session's own conversation in "Pick a conversation to read it here before you resume" — instead all four sessions (very different topics: a scroll-stick bug, a theme-contrast pass, a sync-health note, and a UX reference idea) show the exact same chat transcript text ("fine, leave it. run the tests" / "All 41 in that file pass…") in the preview pane. Only the title, tags, model and folder update correctly; the actual message history does not. This defeats the purpose of previewing before you resume — you cannot tell the conversations apart by content. — Welcome Back screen, preview pane — `scratch/ux2/02-preview/midnight/preview-first-session.png`, `scratch/ux2/03-preview/midnight/preview-third-session.png`, `scratch/ux2/03-preview/midnight/preview-fourth-session.png`

- U4 rejected — approved design: Start fresh returns to the usual start screen (questions deck Q-where). Finding: Expected "Start fresh" to drop me straight into a new, ready-to-type conversation — instead it goes to an intermediate "No Active Session" screen with two more buttons ("New Session" / "Resume Session"); clicking "New Session" then opens a project-folder/model picker that needs a third click ("Create Session") before you can actually type. Three steps for a button that says "fresh." — Welcome Back → No Active Session → New Session dialog — `scratch/ux2/08-startfresh/midnight/start-fresh-click.png`, `scratch/ux2/09-newsession/midnight/after-new-session.png`

- U5 rejected — Destin dictated this copy word for word (review-2 B-quit); raised with him in chat instead. Finding: Wording, close-window warning: "You have 11 active sessions - proceed?" mixes a statement and a question with a bare hyphen. Shorter/clearer: "You have 11 active sessions. Close them all?" — Close window dialog — `scratch/ux2/20-closewarning/midnight/close-warning.png`

- U6 rejected — same dictated copy as U5; raised with him in chat. Finding: Wording, same dialog: "Closing this window will end your active sessions. Would you like an offer to resume these sessions the next time you launch YouCoded?" is two sentences to say what the toggle right below it ("Resume on Next Launch?") already says. Propose dropping the second sentence entirely and keeping just "Closing this window will end all 11 sessions." — Close window dialog — same screenshot as U5

- U7 rejected — the button is labelled "Close" (CloseButton default); a screen reader announcing it inside the dialog named "Close window" is correct, not a doubled label. Finding: The close-window dialog's "X" button reads to assistive tech as "Close Close window" (the word "Close" is duplicated — looks like an aria-label template bug prefixing "Close " onto a title that already starts with "Close"). — Close window dialog — same screenshot as U5

- U8 rejected — the ✕-as-cancel footer matches the approved picture and CloseSessionPrompt (P-15 removed its Cancel). Finding: The close-window warning about ending 11 active sessions has only a red "Close window" button and a small X icon; there is no explicit "Cancel" or "Keep working" text button. For a warning about a somewhat destructive action, relying on users to notice the corner X is risky. — Close window dialog — same screenshot as U5

- U9 rejected — pre-existing status-bar chip, out of scope (as UX review 1, U4/U7). Finding: "PERMISSION UNKNOWN" (bottom-left status chip, visible on the close-warning screen) is developer-facing language a normal user won't understand ("unknown" permission for what?), and it also fails contrast (red text ratio 4.11 vs. the 4.5 needed for its size). — main chat window status bar — `scratch/ux2/20-closewarning/midnight/close-warning.png`

- U10 rejected — pre-existing tool-row styling, out of scope. Finding: Minor contrast: several small "|" separator glyphs inside collapsed tool-call rows are low-contrast in the Midnight theme (ratios 2.0–2.5 vs. 4.5 needed), on both the Welcome Back and close-warning screens. Not blocking, but noticeable if you're relying on them to distinguish grouped items. — `scratch/ux2/10-resumeall/…`, `scratch/ux2/20-closewarning/…` manifests

- U11 rejected — pre-existing rename dialog copy, out of scope. Finding: Wording, rename dialog: "Automatic naming won't change this name." is a little abstract for a first-time user — it assumes you already know the app renames chats automatically. A clearer version: "This name is now fixed — it won't be auto-renamed later." — Welcome Back → Rename session dialog — `scratch/ux2/06-rename/midnight/rename-click.png`

- U12 already handled — the Resume list is chunk-revealed with its own stress pin; this branch does not change it, and search was fast. Finding: Inconclusive / needs a human check: with the simulated 2000-conversation Resume list open (stress scenario), typing into "Search sessions…" filtered instantly with no visible lag — good. But when I tried to force-scroll the list programmatically, one attempt made the whole test script stop responding for 90+ seconds. I could not tell whether that was a real rendering slowdown in the list (e.g. not virtualizing 2000 rows) or just my own scripted click hitting the wrong element — a person actually scrolling with a mouse wheel/trackpad would be a more reliable check than what I could script in the time I had. — "Resume Session" list under `scenario=stress&stressRows=2000` — no reliable screenshot (script did not complete); working screenshot of the list itself: `scratch/ux2/20-searchstress/midnight/resume-list-then-search.png`

Not reported as findings (working as designed / fake data): the repeated "7/29/2025" dates and duplicate session titles in the stress list, the instant/identical assistant replies, and the toolbar used to switch scenarios.

**Summary:** I was able to complete both tasks — reopening some/all/none of the crashed sessions, and reading the close-window warning — without hitting a hard dead end, so the core "get back to work" path works. The single most confusing moment was clicking "Resume all 4": three sessions opened invisibly behind the still-open dialog while its text quietly changed from plural to singular, so it looked like nothing had happened until I noticed the tabs at the top of the window. A first-time user recovering from a crash — already a stressful moment — deserves a clear "3 resumed, 1 needs your input" message instead of a dialog that just gets smaller.
