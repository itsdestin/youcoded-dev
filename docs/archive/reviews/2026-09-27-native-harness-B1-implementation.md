## Interfaces and ownership

- `youcoded/desktop/src/main/harness/injection/project-instructions.ts`: async `prepareProjectInstructions(cwd, budgetTokens, fixtureBoundary?)` walks filesystem root → cwd. One file per directory, AGENTS.md preferred. An optional boundary is used **only** by evaluator fixtures to avoid inheriting actual machine instructions. Each `ProjectInstructionFile` contains `path`, `name`, `full`, `text`, `truncated`, optional `note`; one aggregate character allowance charges source tags and divides the remaining text allotment. No imports or personal-global location lookup.
- `prompt-assembly.ts` accepts optional `projectInstructionFiles` and joins their source-labelled fitted text into the existing `project` part. Its legacy synchronous single-file fallback remains for old direct callers/Claude Code context; production host and evaluator supply a captured inventory. No model-switch prompt refresh.
- `native-session-host.ts`: root create/resume and specialist create/resume await the inventory alongside git snapshot and trigger index. The root live entry holds the same snapshot used for its prompt and context summary. `sessionContextText(sessionId, 'project', id?)` selects only a captured path (no id selects nearest); unknown ids return not-found. No new IPC channel: existing optional id travels through desktop/remote. Android remains unsupported.
- `youcoded/desktop/src/shared/project-instruction-summary.ts`, `types.ts`, `session-context-facts.ts`, `SessionContextPopup.tsx`: optional `projectInstructionFiles` summaries, no bodies in initial event; Project tab repeats existing file rows and requests captured text per row. Old single-file/Claude Code records retain their existing presentation.
- `eval/run-case.ts` uses the same inventory fitter with a disposable fixture boundary. Documentation updated in `youcoded/docs/native-runtime.md` and `.claude/rules/harness-tools.md` for B1 claims.
