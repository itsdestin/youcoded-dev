The reviewer found two real port blockers. `git show HEAD:desktop/src/main/conversations/conversation-store.ts` showed the earlier unlocked `remove()` and pre-lock claim reads too; these races were **pre-existing**, but the port was not complete while they remained. Added deterministic signal/lock-barrier tests to `desktop/tests/conversation-store.test.ts`. Before the correction, `npx vitest run tests/conversation-store.test.ts -t 'remove while heal|invalid canonical leaves a validated claim'` exited 1: 2 failed, 53 skipped (`scratch/sync-bug-probes/heal-review-red.log`). The removal test paused heal after reading the claim and before its canonical lock; remove wiped the claims, then heal recreated the canonical. The other test found that repeated reads renamed the same valid claim while an invalid canonical prevented committing it.

Accepted and narrowly fixed: removal now takes the existing canonical `mutateFileUnderLock` lock, deletes canonical and currently present claims inside it (null callback = no replacement), and fails honestly on lock timeout. Heal checks an invalid canonical before claiming and re-reads claimed files **inside that same lock** before folding, refusing to seed from stale records if remove wiped all claims. No new locks, tombstones, or generalized deletion semantics; the only remove caller remains phantom-native prune in `service.ts`. `npx vitest run tests/conversation-store.test.ts` → exit 0, 55 passed (`scratch/sync-bug-probes/heal-review-green.log`).
