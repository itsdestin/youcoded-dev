## Implementation triage

- U1: dropped from this bounded repair. A missing-project conversation correctly cannot start; adding folder-location/recovery UI is separate from ownership admission. No unavailable conversation was enabled just to make the test pass.
- U2: fixed in the workbench. The tester used an inline chatsearch conversation card, whose UUID fixture is separate from the Resume Browser's `wb-past-*` rows. The mock only initialized the latter, so it fabricated a permanent startup stall. A regression test first failed on the placeholder title, then passed after using the existing reference fixture index. An independent real-renderer probe repeated the inline-card handoff and reached `Permission ask timeout` with `initializing:false` (`scratch/lease-handoff/ux/inline-resume-fixed.png`). This fixes simulator fidelity; it is not evidence of real-device startup latency.
- U3: already filed in `docs/roadmap/sync.md` (“there is no way in the app to find the '(from …)' copy or pick which version to keep”). Retained as that separate parked recovery-interface decision, not silently invented during this repair. Q-6 in the repair deck addresses warning placement, not a new recovery interface.

**Simulator limits:** Backend, people and files were simulated; this did not test two real computers, real handoff delivery, real synchronization, or network latency. Browser automation did not test touch or a high-density display. No production app or paid calls were used.
