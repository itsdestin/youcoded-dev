## Change

- `youcoded/desktop/src/main/harness/tools/bash.ts`: foreground stdout/stderr/close/error listeners remain installed while `ctx.shells.adopt` attempts setup, and only the foreground's own listeners are removed after successful registration. The deadline callback checks whether a close/abort already settled the call. A failed adoption is contained in the deadline callback, attempts cleanup using existing `killTree(child, { graceMs: 0 })`, and resolves once with the actual setup detail, output so far and an explicit note that exit was not confirmed. No background id, log-success or cwd/env persistence is invented. If an abort/close settles reentrantly during a successful adoption, the registry owns the run's cleanup and the previous result wins; it does not claim a successful handoff. The original child is adopted, never respawned.
- `youcoded/desktop/src/main/harness/shell-registry.ts`: explicit background `start()` now catches registration failure after spawn, requests immediate cleanup of its spawned child and returns the existing typed `{ok:false,reason:'spawn-failed',detail}` outcome. It attaches a late child-error handler so an asynchronous spawn error cannot become unhandled after setup fails. Newly created log streams receive an error handler immediately, before the old-file sweep, preserving the existing registered-run memory-tail fallback on asynchronous stream failure. `killTree` and the C2 delayed escalation semantics are unchanged.
- `youcoded/desktop/tests/bash-background.test.ts`: real foreground process emitting `early` plus a long-running continuation; forced EACCES-style `adopt` exception must settle, keep early output, leave no phantom run, and avoid a success notice. Reentrant abort/failure and abort/success cases pin one outcome and registry ownership. Existing ordinary handoff, no cwd/env persistence, deadline/no-registry and background cap cases remain in the owning suite.
- `youcoded/desktop/tests/shell-registry.test.ts`: an obstruction occupying only a unique disposable test-session log directory forces real `register` setup failure after spawn; assert typed failure and no published run. An asynchronous registered log-stream error leaves the in-memory tail and one exit event. Existing same-process adoption and registry tests remain.
- Removed only the now-superseded **untracked** `youcoded/desktop/tests/bash-adopt-audit-disposable.test.ts` after the desired owning cases passed. Did not remove any other audit probe.

## Boundaries and known limits

Setup failure cleanup uses the existing immediate `killTree` behavior; C2's surviving-descendant/process-group-reuse problem is **deferred** and this change makes no new promise to kill every descendant or confirm a process exit. A failed log write **after** registration remains an owned run with memory-tail fallback; it is not reported as a failed registration. C3 does not change the public Bash tool result schema, `ShellStartResult` union or service signature. No interactive test on the built app and no paid model run were performed.
