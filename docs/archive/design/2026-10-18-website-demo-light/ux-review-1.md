# Website demo light — context-free UX review 1

Tested the practice app using only the tester kit and numbered explore clicks. Desktop start: `node scripts/shoot/explore.mjs start --scenario site --theme youcoded --params reply=site`; fresh narrow start: `node scripts/shoot/explore.mjs start --width 390 --scenario site --theme youcoded --params reply=site`. Desktop was 1440px wide; narrow was 390px. No source, plans, design files or previous reports were inspected. No real home or bank connection was attempted. Fake data/backend were treated as intentional.

## Triage

- U1 accepted: fix the shared narrow Pages-list selection to use the existing full-width focused page host; desktop remains unchanged. Include this shared phone effect in the visual review.
- U2 already handled: the numbered explore tool cannot enumerate sandboxed page controls. A frame-aware DOM check against the built website successfully clicked a Home light (visible state and fake-house state changed) and Finance’s Spending tab (selected state and chart heading changed), with no page errors. This does not claim touch testing.
- U3 rejected: accounting-style negative amounts are an existing approved Money design decision (round 3, `money-page.html` money() comment and `money-page.test.ts` existing assertions). Do not overturn that decision as an embed refresh.
- U4 rejected: the upper label explicitly compares the last 30 days; the chart’s lower label explicitly names its own start date. A calendar-month chart can span 31 days and legitimately have a different change. No false financial calculation was demonstrated.
- U5 rejected for this scope: this is the existing Home tile summary’s truncation, not a new demo-specific layout. Preserve the existing page design and show the actual Home view in R-3 for visual judgment rather than silently redesigning its cards during an embed update.
- U6 accepted and applied: public site scenarios reuse the everyday/student shortcut list, without changing the internal practice scenario. A focused test failed with Git Status/Review PR/Fix Tests present and passed after filtering them from `site` only.

## Findings

- U1 — Expected selecting Home at 390px to give the devices enough room to read and operate / the Pages list continues occupying roughly 250px, leaving Home in a roughly 120px strip. The Home heading is overlapped by Edit/settings controls; status chips wrap or collide, and the floor lamp and thermostat extend beyond the right edge. I could not read the full device cards. Clicking the top “Open pages” button in an attempt to collapse the list instead returned to chat, rather than leaving Home full-width. Outcome: Home is not understandable through this narrow-screen discovery route; use a list-to-page transition with a back control rather than keeping both columns. — Home, 390px — `ux-evidence/20261019-004100-03-click.png`
- U2 — Expected to change a light/thermostat and open Spending or an account / explore provided no numbered controls inside either page, although the desktop screenshots visibly contain device controls and Finance tabs. Home's list contained only 10 outer-window controls, even after `look --all`; Finance's contained only nine. Outcome: device changes and account/spending navigation are **unverified**, not demonstrated broken. This is an interaction/testing blocker under the required numbered-click method, not proof that the visible controls fail for a person with a mouse. — Home and Finance, desktop — `ux-evidence/20261019-004012-01-click.png`; `ux-evidence/20261019-004012-02-click.png`
- U3 — Expected the net-worth headline to state plainly whether I am above or below zero / it reads “$(35,329)” and “TOTAL OWED $(64,025)”. Parentheses are an accounting convention I have to interpret, and placing them after the dollar sign makes the headline look unusual. Outcome: use “−$35,329” for negative net worth and “$64,025” under Total owed, where the heading already explains the direction. — Finance, desktop — `ux-evidence/20261019-004012-02-click.png`
- U4 — Expected the selected “1M” net-worth view to give one clear summary of the change / the same card says “Down $549 in 30 days” above the chart and “Up $393 since Sep 5” below a chart running Sep 5–Oct 6. These may be different comparisons, but the page does not explain why two approximately monthly summaries point opposite ways. Outcome: make the comparison periods explicit, or show only the summary for the selected chart period; shorter suggested wording is “Up $393 this period” if that is the plotted comparison. — Finance, desktop — `ux-evidence/20261019-004012-02-click.png`
- U5 — Expected an important device problem to be readable / the Study Lights summary is cut off as “3 of 3 on · 1 not res...” even at desktop width, so I cannot tell the full problem from its summary. Outcome: preserve the fault wording rather than truncating it; a shorter label such as “3 on · 1 offline” would work only if offline is the actual condition, otherwise use “1 not responding” on another line. — Home, desktop — `ux-evidence/20261019-004012-01-click.png`
- U6 — Expected ordinary-user conversation shortcuts to be self-explanatory / “Git Status”, “Review PR”, and “Fix Tests” are prominent beside Journal and Inbox. “PR” and “Git” are unexplained developer terms; they distracted from an otherwise ordinary planning conversation. Outcome: prefer audience-relevant shortcuts, or expand “Review PR” to “Review code changes” when a developer shortcut is appropriate. — Conversation, desktop and 390px — `ux-evidence/20261019-004012-00-look.png`; `ux-evidence/20261019-004100-00-look.png`
