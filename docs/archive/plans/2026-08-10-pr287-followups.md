### Task 2: Type the `sessionIdle` flag

**Why:** `sessionIdle` is written at `ipc-handlers.ts:2428` and read at `App.tsx:1189`, connected by nothing but a matching string literal — `evt.sender.send`'s args are `any[]`, and `sessionIdle` appears in `shared/types.ts` **only inside a comment** (line 124), never as a declared field. The 14 tests PR #287 added all dispatch the reducer action directly; none exercise the event→action wiring. If either literal drifts, the gate reads `undefined → false`, the reap silently stops happening, and the entire suite stays green.

Purely additive: zero runtime effect, and `replay-complete` is never persisted and never reaches the Kotlin serializer, so there is no parity concern.

> **Declaring the field is NOT enough on its own — measured, 2026-08-10.** I added `sessionIdle?: boolean` to the interface, typo'd the producer to `sessionIdIe`, and ran `tsc --noEmit`: **it passed.** `evt.sender.send(channel, ...args: any[])` erases the contextual type, so the object literal is never checked against `TranscriptEvent` at all. The declaration alone is documentation, not a guard.
>
> The producer must **also** be annotated so the literal is contextually typed. With both changes, the same typo produces:
> ```
> error TS2561: Object literal may only specify known properties, but 'sessionIdIe'
> does not exist in type '{ ... sessionIdle?: boolean | undefined; }'.
> Did you mean to write 'sessionIdle'?
> ```
> `ipc-handlers.ts` already imports `TranscriptEvent` (line 10) and already uses this exact annotated-const pattern at line 599, so this follows the file's own convention.

## Not a task: the residual pasted-filepath gap

**This needs a product decision before anyone writes code. Do not implement it from this document.**

PR #287's discriminator (`cmd.includes('/', 1)`) tests the **command word only**, so it misses any path whose first segment has no second slash. Measured by running the real dispatcher, 2026-08-10:

```
/My Files/notes.md   → invoke-skill  skill="my"        args="Files/notes.md"
/Users Shared/x/y.md → invoke-skill  skill="users"     args="Shared/x/y.md"
/README.md           → invoke-skill  skill="readme.md"
/etc                 → invoke-skill  skill="etc"
/home                → invoke-skill  skill="home"
```

All five are still consumed by the native route and the input is still deleted.

**Why it is not a discriminator problem.** `InputBar.tsx:380` does `void runNativeSlashAction(...); return true;` — fire-and-forget. `sendMessage` is synchronous and returns a boolean, and its caller (`InputBar.tsx:565-566`) clears the draft on `true`. So the box is cleared before the skill result is known. `runNativeSkill` (`native-slash-actions.ts:159-181`) *does* return `false` on not-found, and main already knows the skill does not exist — the renderer just discards the answer. No tightening of the string test fixes that.

**Three viable shapes, in rough order of increasing cost and correctness:**

1. **Restore the draft on failure.** Thread an `onRestoreDraft?: (text: string) => void` through `NativeActionDeps` and call it in `runNativeSkill`'s failure branch. Smallest change, keeps the happy path feeling instant. Downside: the box clears and then repopulates ~a round-trip later, and the user still gets a "Couldn't run /my" toast for text that was never a command.
2. **Fall through to sending it as a normal message when the skill is not found.** Matches what Claude Code sessions already do (`passthrough`), which is the behaviour PR #287's body says it is restoring. Needs the raw text carried to the failure point and a "send as message" callback. Best user outcome; medium cost.
3. **Resolve against the skill catalog in the dispatcher** so an unknown `/token` never produces an `invoke-skill` intent at all. Closes the class at the source, including the PR body's "pasted URL or regex would hit it too" concern. The dispatcher's own comment (`slash-command-dispatcher.ts:76-85`) says plumbing the installed-skill list into the renderer was deliberately avoided, so this reverses a standing decision.

**Recommendation: option 2.** It is the only one where a pasted path does what the user obviously meant, and it makes native match CC rather than inventing a third behaviour. But it changes what happens on a genuine typo (`/compcat` would be sent to the model as a message instead of toasting), so it is Destin's call, not the implementer's.

The PR body already flags the underlying question — whether an unrecognized `/`-prefixed token should be *assumed* to be a skill — as unsettled, with a ROADMAP entry open.
