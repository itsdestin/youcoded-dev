# Swapping models mid-turn bills the WHOLE turn at the new model's rate

**History:** added 2026-08-27 (old ROADMAP.md L163). Re-verified against `origin/master` 2026-09-01.

## Symptom

Change models while an answer is still streaming (plausible whenever someone switches
away from a slow local model mid-answer). The turn that was in progress is priced
entirely at the new model's rate and reported under the new model's name.

**Measured, not inferred** (2026-08-27, while pinning Task 24 of the status-bar work):
swapping `m-cheap` → `m-dear` ~30 ms into a still-streaming turn produced
`{"n":1,"model":"m-dear","cost":70}` for a turn that should have cost 7.

## Mechanism

`setBinding` (`youcoded/desktop/src/main/harness/harness-session.ts`, ~L810) writes
`this.opts.pricing`, `this.opts.free` and `this.binding` immediately. But a turn's
`costUsd` is computed at the `turn-complete` emit from the **live** `opts`:
<!-- claim: {"path": "youcoded/desktop/src/main/harness/harness-session.ts", "contains": "const costUsd = this\\.opts\\.free \\? null : costForUsage\\(turnUsage, this\\.opts\\.pricing\\)"} -->

and `model` on the same emit is read from `this.binding.modelId`. So every token already
generated by the old model is re-priced at the new one, and attributed to it.

This contradicts two of the file's own comments: `setBinding`'s doc line ("next turn uses
the new binding") and the `HarnessSessionOpts.pricing` field ("a turn is never repriced
retroactively"). Both describe the intended behaviour, not the actual one.

Nothing upstream prevents the race: `NATIVE_SET_BINDING`
(`youcoded/desktop/src/main/ipc-handlers.ts`, ~L2805) forwards straight to
`nativeHost.setBinding` with no check for a turn in flight.

## Fix shape

Snapshot the price card + model id at turn START and price the `turn-complete` emit from
the snapshot rather than reading live `opts`. Deliberately not fixed inside Task 24, which
was authorised only to add guards, not to change pricing behaviour.
