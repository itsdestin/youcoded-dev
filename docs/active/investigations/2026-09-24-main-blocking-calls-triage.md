# Main-process blocking calls — triage

**Read against:** app master `7247ad7e` (2026-09-23), allowlist `desktop/tests/main-blocking-calls.allowlist.json`, guard `desktop/tests/main-blocking-calls.test.ts`.
**Scope:** all 708 `unreviewed-hot-path-candidate` entries (835 calls), grouped into 402 (file, function) groups. Every group was traced to its callers (main, IPC handlers, renderer trigger) by six read-only passes; each pass verified 1:1 coverage of its input. Spot re-verified by hand: `appearance:set` (renderer `persistAppearance` has no debounce, `theme-context.tsx:153`), `SessionStore.has()` → `listSessionFiles()` (`harness/session-store.ts:350`), `readTranscriptPage` async-with-no-await (`transcript-page.ts:107`).

**For Destin, in plain words.** The app has one "switchboard" process that every window waits on. About 700 places in it do disk or command work that makes every window wait until it finishes. About half of them only run at launch, during installs, or when you press a rare settings button — harmless. About 60 groups sit on paths you hit all the time: opening or scrolling a conversation, finishing a reply, the background sync every 15 s–2 min, the Marketplace, loading a local model, dragging a theme slider. Those are the ones worth fixing; the plan below splits them into batches that separate workers can do at the same time without touching the same files.

## Headline

- **Nothing runs per streamed word or per terminal chunk.** No entry is on the per-token/PTY path (class a = 0). The worst offenders are per-reply, per-sync-cycle, per-scroll and per-click.
- **33 groups score 4–5** (plausible felt hitch today), **31 score 3** (hot but small, or large but gated), **338 score 1–2**.
- **Top felt symptoms, by cause:**
  1. *End of every reply* — `NativeHome.listSessionFiles` (full readdir of every native session, via auto-naming's `hasTitle` → `SessionStore.has`), conversation-store `heal`/`get` and naming-store `foldConflicts` (readdir of the whole conversation dir on every per-turn naming check and ~5 s activity upsert).
  2. *Opening / scrolling back a conversation, opening the buddy* — `readTranscriptPage` (async but no `await`) reads up to 2 MB synchronously and re-reads **every** subagent transcript (`SubagentWatcher.getHistory`) on each page.
  3. *Closing a session* — chat-search `refreshTurns`/`readChunk` read up to 8 MB per changed conversation and rewrite a ~1.5 MB meta file synchronously.
  4. *Background sync* — `SpaceManager.read/write` rewrite `sync-spaces.json` on every sync success per space; git-transport lock/oversize scans every cycle (each small).
  5. *Loading a local model* — `residentBytesForModel` scans all of `/proc` every 400 ms while a model loads; `cache-scan` readdir+stat on the 10 s / 400 ms model poll.
  6. *Clicks* — dragging a Theme-editor glass slider (sync read-merge-write per tick, no debounce), Marketplace open (multi-MB catalog cache parsed sync, plus a second full parse just for the ETag), Import existing folder (deliberate 2 s sync walk; unbounded sync `cpSync` across drives).
- **Reclassify 327 entries** (116 → startup-or-shutdown-only, 211 → user-rare) and **delete ~21 dead entries** (11 groups) — that alone shrinks "unreviewed" from 708 to ~360, and the fix batches below remove most of the rest that matter.

## Method notes and caveats

- Six parallel read-only passes, one per subsystem; each row carries caller evidence. Full per-group data (all 402 groups) was generated as JSONL and is summarised here; rows below score 3 are not individually listed.
- Scores are judgement: "large" = grows with history, a recursive walk, a multi-MB file, or a child process. No timings were measured (no app launches). A perf-lab measurement of B1/B2/B5 before/after would confirm the ranking.
- Branch conflict data: `git branch -r --no-merged origin/master` on 2026-09-24, dependabot excluded; local worktrees with only uncommitted work were checked and had no `desktop/src/main` changes.
