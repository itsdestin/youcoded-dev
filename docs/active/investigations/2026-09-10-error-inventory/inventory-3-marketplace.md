## Lead verdicts

- **"InstallingFooterStrip says 'Failed to install' for uninstall and update failures" — CONFIRMED, and wider than reported.** All three mutations write to one map with one key shape, and the strip has one sentence. The refresh calls that run *after* a successful mutation sit inside the same `try`, so a refresh failure is also reported as a failed install. See row 1.
- **"handler-utils turns non-API exceptions into status 0" — CONFIRMED.** `main/handler-utils.ts:22-23`: `const message = e instanceof Error ? e.message : String(e); return { ok: false, status: 0, message }; // status:0 = non-API error (network, parse, etc.)`.
- **"Renderer code reads status 0 / TypeError as offline" — REFUTED for this scope.** A search of every in-scope file for `status === 0`, `status: 0`, `TypeError`, `navigator.onLine` and `offline` finds only comments. Nothing in scope *displays* "offline". `worker-health-context` receives `reportResult(false)` from stats failures, but its only consumer is `StatsWithHealthBridge.tsx`, which renders nothing. The status-0 problem here is different: the Node message (e.g. `fetch failed`) is shown **verbatim** (rows 32, 34) or folded into generic copy (rows 29, 30).
