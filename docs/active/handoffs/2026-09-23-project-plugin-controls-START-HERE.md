## Product goal / agreed constraints

- One installed copy of a plugin, **per-project automatic availability**. When an enabled skill is relevant, the assistant sees its catalog metadata and reads full instructions only on use; no bulk injection. A skill paused for automatic use remains deliberately callable with `/` or the drawer; invoking it does not change the project setting. Plugin master off pauses automatic use while remembering item choices; enabling the master initially enables its parts, then each part can be switched off. An off MCP server has **no tools** in that conversation; changes affect **new conversations only**. No-project/incognito gets no automatically available skills, including Chat Search.
- A newly downloaded marketplace plugin remains installed but starts inactive in every project and immediately offers multi-project setup; leaving the setup keeps it installed and inactive. **Existing** items and newly hand-added skills keep current behavior rather than silently being turned off. Existing project switches must show actual effective availability, not a confusing inherited third state. Ordinary-project bundled defaults (Chat Search, Page Builder, Marketplace Publisher on; Theme Builder off) must not turn off something already working; all four bundled plugins are always on/non-disableable **only in the planned Your Assistant project**. No setting there becomes a global inherited default.
- Enabling servers/hooks that can connect or run automatically requires a risk explanation and confirmation *each time*; one confirmation lists affected components for a whole plugin. Discovery of an ordinary skill alone does not. Existing tool permissions remain intact. Exact risk copy and UI still need visual review. Mid-session/on-demand MCP connection is deferred.
- Project choices travel with a synced project; plugin files do **not** auto-install. A missing marketplace item should offer Install on that device; a missing outside item shows its saved choice and a truthful local-add/setup action. Never sync MCP credentials; device-specific connection setup is local. Skill files within a synced project may travel with project file sync if sync is enabled and rules allow; personal `~/.claude/skills/` files do not yet sync. Claude Code settings must not be silently rewritten: consent-based opt-in is later, not first build.
