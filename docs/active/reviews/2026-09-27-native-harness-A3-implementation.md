# Native harness A3 implementation (2026-09-27)

Scope: ordinary busy root input only. A1/A2 uncommitted changes preserved. No commits, live app, paid calls, new IPC/events, child-steer rewrite, or A4/Batch B implementation.

## Implementation

- `youcoded/desktop/src/main/harness/harness-session.ts`: the opening send and busy correction share the human user-event/image/history-origin/accepted-capture path. The running turn retains its abort and budgets. After a stream, before each announced tool call, and before natural completion the driver tries the synchronous root claim. It records real completed calls, pairs remaining unexecuted calls as **not run**, then inserts human input and requests the model again. Interrupt/dismissal/error paths remain exits; the host handles their surviving queue.
- `youcoded/desktop/src/main/harness/native-session-host.ts`: only the captured live root session can shift a ready FIFO head while in flight; generation, quiesce and readiness are checked synchronously. Its claim offers `restore()` for a failed synchronous acceptance; the normal host drain handles it after settlement. Root creation and resume wire this callback; children do not. The existing setImmediate acknowledgement boundary, queue IDs, Cancel/Edit and post-Stop report hold remain unchanged.
- `youcoded/desktop/src/main/harness/busy-message-boundary.ts`: focused extraction for the claim/restore seam, shared human event/history append, and superseded tool-group pairing. Internal `HarnessSessionOpts.takeReadyBusyMessage()` returns `{ id, text, attachments, restore? } | undefined`; no public IPC shape changes. The old reducer's pending/queue removal paths already handle the real user-message event; no UI or reducer change needed.

## Limits / follow-up review points

- No new renderer presentation was needed; this is event/queue correctness, not a visual change. Existing 9 named suites verify the renderer and history paths; no interactive/dev screenshot or Android test was run (desktop-only native root changes).
- The claim can be restored if synchronous event acceptance throws. A synthetic throwing-listener test covers restoration of an unaccepted message; no transaction across external listeners is introduced.
