- D10 accepted — major — §1's fix for D8 ("written through on every change... not coalesced") is anchored to "`app.on('before-quit')` / shutdown path: flush pending write (awaited, bounded 1 s)" — wording that names the `before-quit` EVENT specifically, not the shared `shutdownApp()`/`runShutdown()` function the way §4.5's sibling fix for D2/D6 does ("the settle step lives in ONE function, `settlePendingCloseRequests()`, called at the top of `shutdownApp()` itself — every route passes through it"). If an implementer reads §1 literally and wires the write-flush into the `before-quit` listener body instead of into `runShutdown()`, the flush is skipped entirely on the SIGTERM/SIGINT route (`main.ts:2486-2489`), which calls `shutdownApp()` directly and never fires `before-quit` — reproducing, for the write-flush, the exact bug class this file's own header comment on `shutdownApp` documents as having already shipped once for OTHER cleanup ("every quit route that does NOT go through window-all-closed... ran none of it... An OS shutdown/logout SIGTERM bypasses Electron's quit events entirely, on every platform", `main.ts:2387-2397`) and that review round 2's D6 had to independently catch for the sibling close-request-settlement mechanism in this SAME design. The practical impact is a silent violation of the S-other-quit guarantee this feature exists to provide: a session started or first-messaged in the seconds before an OS shutdown/logout/`kill` never reaches disk and is quietly not offered back next launch — for OS shutdown specifically, arguably the single most common real-world case Welcome Back targets, not an edge case. — evidence: design doc lines 47-53 (write-through fix) and line 59 ("`app.on('before-quit')` / shutdown path: flush pending write") vs. lines 121-125 (§4.5's explicit "ONE function... every route passes through it" framing for the analogous fix); `main.ts:2474-2480` (`before-quit`) vs. `main.ts:2486-2489` (`process.on('SIGTERM'|'SIGINT')` — separate listener, calls `shutdownApp()` directly, never fires `before-quit`); `main.ts:2407-2429` (`shutdownApp`/`runShutdown`, the one function both routes share). — suggested fix: reword §1's bullet to state explicitly that the flush is invoked from inside `runShutdown()` (or at the top of `shutdownApp()`, same funnel as `settlePendingCloseRequests()`), not from the `before-quit` event handler directly, so both routes get it automatically; add a test that the SIGTERM path also awaits the flush (mirrors the "SIGTERM path settles too" test already called for in §6 for the close-request mechanism).

Nothing else rises to a real, previously-unflagged defect. D1–D9 are each addressed correctly and completely as now written: D1 (holder-takeover untrack) and the parallel remote-server `session:destroy` bypass are both named with call-site evidence in §2's table; D2/D6 (whole-app-quit vs. pending close-request, menu-quit vs. SIGTERM) are resolved by routing `settlePendingCloseRequests()` through the one shared `shutdownApp()` funnel, which the code confirms is genuinely shared (`main.ts:2474-2489`); D3 (leader-window gating) is honestly still marked "Add:" in §5 and the renderer's `welcomeBackAsked` effect (`App.tsx:3496-3506`) confirms it isn't built yet — the existing `isLeader`/`leaderWindowId` plumbing (`App.tsx:292-293`) is available for that gate whenever it lands; D4 (timeout path must still destroy sessions) is now explicit in §4 step 2; D5 (startup-read timing) is now stated precisely ("before `createWindow()` is called") plus belted with the `ready` promise; D7 (hand-authored IPC parity block, not "automatic") and D8 (write-through instead of debounce, residual async-write gap documented) are both correctly rewritten; D9 (requestId + `close-request-cancelled` + renderer clearing `quitPrompt`) is fully specified in §3's channel table and §6's test list, consistent with the still-unbuilt renderer state (`App.tsx:3542-3549`, no `requestId` on `quitPrompt` yet, `mock-shim.ts`/`mock-only.ts` not yet carrying the fifth channel) — expected for a design not yet implemented, not a defect in the design text itself.
