P-3 — Themes dialog (Settings → Appearance) mixed

Correction to the ledger

The ledger said “Browse all themes →” and “Browse Theme Marketplace” open the same screen. They do not. The first opens Your Library › Themes (themes already installed on this machine — the grid above it only shows your starred ones); the second opens the Marketplace (themes you can install). The real problem is smaller: the two names sound like the same thing, so you cannot tell which one you want.

Measured

  1. Cards jump height. The active theme's card gets a second line (active), and because the grid stretches each row, its neighbour grows too and shows an empty strip with a pencil floating in it. In the crop, Dark is about 30 px taller than Crème (65 vs 34 px) for no reason.
  2. “Edit” on a built-in opens an empty dialog. All four built-ins (Midnight, Dark, Light, Crème) are solid-colour themes, so their edit screen has nothing to offer: the whole 588 px-tall panel holds one sentence saying it is locked. The pencil promises an editor and delivers a notice.
  3. The first button is a fourth button style. Browse all themes → is a hand-rolled panel-coloured box, not one of the app's shared button variants; the two below it are the shared primary and secondary. Three stacked full-width buttons in three styles.

What I would change

  • Every card the same height: the active label moves onto the name line (small badge at the right, where the star already sits), so no card ever grows.
  • The pencil on a built-in becomes disabled with a tooltip: “Built-in themes can't be edited — make a copy with Build New Theme with Claude.” Community themes keep a live pencil (they have real glass sliders). Alternative: hide the pencil on built-ins entirely — I recommend against that, because the tooltip is the only place that explains why.
  • Honest names: All installed themes → (opens Your Library) and Get more themes (opens the Marketplace). Build New Theme with Claude keeps its name.
  • judgment The first button stops being a third bordered box: it becomes a quiet text-link row under the grid (All installed themes →), leaving one primary (Build) and one secondary (Get more themes). Reject this and the three boxes stay, just renamed.

What you will notice, and the risks

  • The Themes grid stops looking broken when a theme is active. The pencil on Midnight/Dark/Light/Crème goes grey and explains itself on hover instead of opening a dead end.
  • Risk: someone who learned “Browse all themes” means “my installed themes” now reads a new label — but the old label never said that, so this can only get clearer.

P-21 — Marketplace cards — gold hero border, ragged theme rows, “1 installs” measured

Measured

  1. The featured card's border is hardcoded gold (#d8a84b, from the featured list's accentColor) in every theme. The other two featured entries carry their own colours too (a blue and a green), so the border changes colour as the carousel turns — and none of the three is ever the theme's. It is the only gold object on the screen next to Halftone's pink, Meadow's green and Light's black; the View details button inside it correctly takes the theme, which makes the border look more wrong.
  2. Theme rows are ragged inside the cards. The card boxes themselves are equal (the grid stretches them), but the content is not: a card only draws its description if it has one, and its likes line only if the count is non-zero. So Cotton Candy Sky, Devil's Garden and Meadow Mist stop at the author line and leave a ~40 px hole, while their neighbours run two lines further and end with a count — five different bottom edges across seven cards.
  3. “1 installs”, “1 likes”. The counts never pluralise (two places in the card, plus the hero rail).

What I would change

  • Hero border = the theme's normal card edge, like every other card. The featured list's colour is dropped from the border entirely (recommended — one fewer colour that is not the theme's). Alternative kept from the guide (T-1): let that colour tint only the small FEATURED eyebrow and the dot pager. I would not: nobody reads a 12 px eyebrow as a brand accent, and it keeps a non-theme colour alive.
  • Theme cards reserve the two description lines whether or not there is a description (long ones already clamp at two), and the counts row keeps its height even when there is nothing to count. Every card's text ends at the same place.
  • 1 install, 1 like; 2 installs, 2 likes.

What you will notice, and the risks

  • The gold outline disappears from the top of the Marketplace in all six themes. Theme rows become even. Grammar is right.
  • Risk: a featured pack's author can no longer colour the hero — that was never a documented feature, and all three current entries use it only to paint this border.

P-2 — Your Library when nothing is installed measured

Measured — and a bug the ledger did not know about

A new install's Library is two headings — Favorites, Installed — over nothing. No sentence, no button, no link, while the Marketplace sits one pill away in the header.

The code actually contains a sentence for each empty section (“Install something from the marketplace to see it here.”) — it has simply never rendered. The section decides “is there content?” by counting its children, and the child is written as condition && <grid>, which when false still counts as one child. So the empty message is unreachable code, on every theme, since the day it was written. That is a bug, not taste, and it gets a pinning test.

What I would change

  • Fix the check so an empty section is actually empty, and render the app's shared EmptyState block (the same one Settings → Permissions, the session drawer and the Resume browser use): a sentence plus a button. Installed → “Nothing installed yet.” + Browse the Marketplace. Favorites → “Star an installed skill and it appears here.” (no button — there is nothing to star yet). Same on the Themes tab, wording adjusted.
  • Nothing changes when the Library has content — that state already matches the Marketplace cards (audit §6c #29).
  • judgment The Skills | Themes switcher under the title is a plain pair of pills at 12 px under a 22 px title; Projects uses bordered tabs with an icon and a count. Adopting that style here is taste — I would leave it for now and let a later phase decide tabs app-wide.

What you will notice, and the risks

  • A brand-new install sees a real empty state with a button instead of two headings and grey whispers. Risk: none for existing users — their Library is not empty.

P-1 — Marketplace filter bar and empty states mixed

Correction to the ledger

The ledger called New / Popular / Featured picks “sorts”. They are not — they are on/off filters like the categories, and you can turn on several. So the bar has two kinds of control, not three: Plugins / Themes (pick one) and eleven filters (any number). The code groups them as Type · Vibe · Meta and separates the groups with a thin line, but paints all thirteen the same.

Measured

  1. Two empty messages at once. When a filter matches nothing, the Themes tab shows “0 results” and, under it, “Nothing matches those filters.” — the same fact twice, with no button to clear the filters.
  2. “Explore everything” with nothing under it. While the registry loads (or when it cannot be reached) the heading renders alone; there is no loading placeholder and no “could not reach the marketplace” state.
  3. Phone width truncates the title to “Ma…”. The right-hand controls take their full width and the title gets what is left.

What I would change

  • One empty state: the count line stays, the duplicate sentence becomes the shared EmptyState with a Clear filters button.
  • Loading: a short row of placeholder cards under the heading; unreachable registry: the shared error block with Retry (this is the rule in docs/error-message-standards.md).
  • Phone: the title keeps its full word; the Library/Back controls shrink first.
  • judgment Plugins / Themes becomes the app's SegmentedTabs control (the same two-way switch the Library uses for Skills | Themes), in the same position; the eleven filters stay pills; the search field gets a magnifier icon. That makes “pick one” and “pick any” look different. Reject it and the bar stays as it is.

What you will notice, and the risks

  • The bar's first two pills turn into a two-position switch; everything else stays where it was, so muscle memory holds. Empty and loading states stop looking broken.
  • Risk: the segmented switch is a visible change on the most-used marketplace control — which is exactly why it is tagged judgment.

P-5 — Projects header card mixed

Correction to the ledger

Two of the ledger's three complaints are stale. Rename and Remove from YouCoded are already the shared small button (the same size as + Add file), not a custom 11 px outline. And the folder cards' “tab” notch is deliberate: it was reworked after your feedback on 2026-07-19 (all four body corners rounded so the nub reads as a folder, not a glitch). I am not proposing to touch either.

Measured

  1. Projects is the only full screen that hides the wallpaper. Its root paints an opaque canvas; Library and Marketplace let the theme's wallpaper through. In Halftone and Meadow, Projects is the one screen that goes flat.
  2. Two accent-filled buttons in one card. New Conversation (primary) and Turn on sync for this project (also primary, nested inside the grey status chip). The design guide's rule is one accent action per card.

What I would change

  • Projects adopts the same transparent root as Library/Marketplace, so the wallpaper shows in community packs. Built-in themes look identical (their canvas is a flat colour anyway).
  • Turn on sync for this project becomes the small secondary button inside the chip; New Conversation stays the card's one accent. judgment — it is the guide's rule, but it makes the sync nudge quieter, which you may not want.
  • Left alone: Rename/Remove, the folder nub, the document previews (the ledger's “~9 px raw Markdown” is the intended thumbnail look).

What you will notice, and the risks

  • In Halftone/Meadow, Projects gets the same see-through background as its two sibling screens. Risk: readability of the header card over a busy wallpaper — the card is already a glass panel, the same as the Marketplace hero, so it should hold; I will show all six themes in the review.
  • The green “Turn on sync” pill becomes an outlined one; users who never noticed it will notice it less.
