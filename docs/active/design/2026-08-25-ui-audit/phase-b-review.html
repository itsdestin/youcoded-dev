P-15 — Every dialog gets a title and a ✕; the close-session footer stops wrapping measured

The problem

Report a bug and Donate were the only dialogs with no title row and no ✕ — Escape was the only way out. The Development menu that leads to the bug report drew its own small uppercase heading instead of the shared header. In the Close session prompt, the footer was the tallest row of the dialog: "Don't show again" wrapped onto two lines beside its toggle and the primary button broke into "Close / session".

(The ledger also said About and Permissions cut their content with no scroll cue — checking the code, both already have the fade. Nothing to do there; the claim was stale.)

What changed

  • The three dialogs now pass a title to the shared Dialog component, which draws the same header every other dialog has (title · ✕). Bug report's title follows the Bug/Feature switch: Report a bug / Request a feature. Donate is titled Support YouCoded. Development is titled Development.
  • Close session: the header also moves to the shared one (title + the session name as subtitle). "Don't show again" becomes its own one-line row with the standard toggle, above a right-aligned Cancel / Close session pair at the small button size, so nothing wraps.
  • Two redundant "portal" wrappers (a leftover from before Dialog handled that itself) were removed — no visible effect.

What you will notice, and the risks

  • Three dialogs are a title row taller and gain a ✕ in the corner.
  • The close-session prompt is one row taller; its buttons are slightly smaller and no longer wrap; the toggle is the standard one.
  • Risk: near zero — this is the existing dialog anatomy applied to the places that skipped it.

P-18 — Tool cards: a real divider instead of a typed "|"; AskUserQuestion looks like its siblings mixed

The problem

Measured: every tool-card header, and the button row of the full-auto stop card, used a typed | character as a divider. It takes the text colour rather than the theme's line colour, sits on the text baseline instead of centred, and screen readers read it aloud. It appears on every tool call in every conversation.

Judgment: the AskUserQuestion card's header stopped after its label (ⓘ | Framework ▾) while every other card reads label ↳ detail; its option rows used their own corner radius and colours; and its radio/checkbox glyph's rounding was written in a way the styling tool cannot see, so it may not have been drawn round at all.

What changed

  • Measured: both dividers are now a 1-pixel line element in the theme's edge colour, centred, invisible to screen readers.
  • Judgment: the AskUserQuestion header now reads Framework ↳ Which framework should the new dashboard use? like its siblings; its option rows use one shared row style (medium corners, edge-coloured border, accent tint when selected); the round/square glyph is now written so it actually renders.

What you will notice, and the risks

  • The pipe character is gone from every tool card; a thin line sits in its place.
  • AskUserQuestion's header carries the first question, so you can read what is being asked without expanding; its rows look like the rest of the app's rows. Risk: this is the card you interact with most, so its shape changing is the most noticeable thing in Phase B — that is why it is tagged judgment.

P-10 — Status bar: readable text, one row on phones; grey chips mixed

The problem

Measured: the status bar's text was 10px, the last surface under the app's 11px floor for anything you read (G-5). At phone width (390px) the chips wrapped to a second row with the theme name orphaned, pushing the composer up.

Judgment: the model chip carried a brand-orange outline while every other chip was grey, so the model read as a warning; the theme chip was drawn as a button but is a label.

What changed

  • Measured: text is 11px (the bar is ~2px taller). Below phone width the bar no longer wraps: the model chip drops its | Auto Effort suffix, the Priority chip shows only its dots, and the theme chip shows a small palette icon (hover for the name).
  • Judgment: the model chip's border and text use the same grey as every chip; the brand colour stays on the model's icon only. The theme chip loses its border and background and shows a small cycle glyph on hover.

What you will notice, and the risks

  • Slightly larger status text; one row on phones.
  • The orange outline is gone — if you used it to find the model at a glance, the icon still carries the colour, but say so if that isn't enough.
