1. When to delegate at all

The transcripts showed helpers hired for single lookups. Everyone else opens with a rule about when a helper is worth it.

YouCoded today (beta 76)

Task tool description
Delegate one focused piece of work to a specialist subagent. The specialist works independently and reports back when it's done.
System prompt
(nothing about specialists except: "<specialists-status>: a helper reporting back, not a new request.")

Claude Code

Agent tool description
Reach for this when the task matches an available agent type, when you have independent work to run in parallel, or when answering would mean reading across several files — delegate it and you keep the conclusion, not the file dumps.

Codex CLI

spawn_agent tool (multi-agent mode)
Do not spawn sub-agents unless the user or applicable AGENTS.md/skill instructions explicitly ask for sub-agents, delegation, or parallel agent work. Requests for depth, thoroughness, research, investigation, or detailed codebase analysis do not count as permission to spawn.
spawn_agent (V2)
Only call this tool for a concrete, bounded subtask that can run independently alongside useful local work; otherwise continue locally.

Hermes Agent

delegate_task tool
USE FOR: reasoning-heavy subtasks, work that would flood your context with intermediate data, or independent parallel workstreams.
Docs
Rule of thumb: Use delegate_task when the subtask requires reasoning, judgment, or multi-step problem solving.

Pi

subagent extension tool
Delegate tasks to specialized subagents with isolated context. Modes: single (agent + task), parallel (tasks array), chain (sequential with {previous} placeholder).
Author's blog
Using a sub-agent mid-session for context gathering is a sign you didn't plan ahead… [the one use he keeps is] code review… Do not read the code yourself. Let the sub-agent do that.

YouCoded proposed (on this branch)

Task tool description
Most work is faster done yourself. Delegate only a self-contained job that also meets one of these: it would fill your context with file contents or search output you only need the conclusion of; it can run while you do something else; or it needs a fresh, unbiased read (a review).

2. When NOT to delegate

Ours had no list at all. Hermes's list is the clearest; Codex's is the strictest.

YouCoded today (beta 76)

Task tool description
(none)

Claude Code

Agent tool description
For a single-fact lookup where you already know the file, symbol, or value, search directly.

Codex CLI

spawn_agent
Do not delegate urgent blocking work when your immediate next step depends on that result.
spawn_agent
Keep work local when the subtask is too difficult to delegate well and when it is tightly coupled, urgent, or likely to block your immediate next step.
Depth refusal

Hermes Agent

delegate_task
DO NOT USE FOR (use these instead):
- Mechanical multi-step work with no reasoning needed -> execute_code
- A single tool call -> call the tool directly
- Tasks needing user interaction -> subagents cannot ask questions
- Durable work that must survive this session -> cronjob or terminal(background=True, notify=True)
Docs
Quick file edits → do them directly

Pi

subagent extension tool
(none)
Author's blog
Spawning multiple sub-agents to implement various features in parallel is an anti-pattern in my book and doesn't work, unless you don't care if your codebase devolves into a pile of garbage.

YouCoded proposed (on this branch)

Task tool description
Do not delegate a single lookup you could do with one Read, Grep or Glob, a quick edit to a file you have already read, a question that needs the user's answer, or the very next step your own work is blocked on.

3. Background runs and what to do while waiting

Our background flag said "Set true for anything long" and the launch reply said "Keep working". The model read that as: launch, then poll and nag.

YouCoded today (beta 76)

background field
Set true for anything long — you keep working and the report is delivered to you automatically when the specialist finishes.
Launch reply
{name} is now working in the background (task_id: …). Their report will be delivered to you automatically when they finish — do not wait or poll. Keep working; a status block at the start of your turns tracks running specialists.

Claude Code

Agent tool description
Subagents run in the background; you'll be notified when one completes. Never fabricate or predict a pending agent's results — the notification is never something you write yourself; if the user asks before it arrives, say it's still running.
Launch reply
The agent is working in the background. You will be notified automatically when it completes… continue other work or respond to the user in the meantime. Do not duplicate this agent's work.

Codex CLI

spawn_agent
While the subagent is running in the background, do meaningful non-overlapping work immediately.
spawn_agent
Call wait_agent very sparingly. Only call wait_agent when you need the result immediately for the next critical-path step and you are blocked until it returns. … Do not repeatedly wait by reflex.

Hermes Agent

delegate_task
Runs in the background: dispatch returns immediately… Results are delivered only BETWEEN your turns: finish whatever does not depend on them, then give a one-line status and END YOUR TURN. Never wait or poll on transcripts, artifact files, or CI for a child.
Launch reply
Results are delivered only after you END YOUR TURN: do anything that does not depend on it, then stop with a one-line status. Do not poll its transcript or artifacts to wait for it.

Pi

Official extension
(foreground only — the parent waits; nothing to do meanwhile)
Community extension (tintinweb)
Pass run_in_background: false only when your very next action depends on the agent's result and nothing else could usefully happen while it runs… Wanting the result "next" is not enough on its own. … do NOT sleep, poll, or proactively check on its progress.

YouCoded proposed (on this branch)

background field
Set true only when you have other useful, non-overlapping work to do while the specialist runs; the report is delivered to you when it finishes. If you would only be waiting for it, leave this false and let the report come back as this call's result.
Launch reply
{name} is now working in the background (task_id: …). Their report will be delivered to you when they finish — do not wait, poll, or send status requests, and do not redo the job yourself. Continue with work that does not depend on it; when nothing else is left, tell the user what is still running and end your turn. A status block at the start of your turns lists running specialists.

4. Don't redo the job, don't nag the helper

72% of our 179 steers were "report now" / "status?" a median 52 seconds apart. Nobody else offers a steer verb without a rule about it.

YouCoded today (beta 76)

Task tool description
To manage a specialist you already started, pass its task_id… Still running: "prompt" is delivered as a steer at its next natural pause.
Rule about frequency
(none)

Claude Code

Agent tool description
Once you've delegated a search, don't also run it yourself — wait for the result.
SendMessage
Use SendMessage with the agent's ID or name to continue a previously spawned agent with its context intact.

Codex CLI

spawn_agent
Do not duplicate work between the main rollout and delegated subtasks.
spawn_agent
Do not redo delegated subagent tasks yourself…

Hermes Agent

delegate_task
'steer' = queue course-correction text into one child (subagent_id + message) without stopping it
Runaway guard (app-enforced)
Blocked delegate_task: this turn has already spawned {count} subagents (limit {cap}). This looks like a runaway delegation loop. Finish the work with the results you have and answer the user.

Pi

tintinweb extension
steer_subagent: Send a steering message to a running agent… Do not duplicate this agent's work.

YouCoded proposed (on this branch)

Task tool description
Once you have delegated a job, do not also do it yourself, and do not send status requests: the report arrives on its own. When nothing else is left for you to do, tell the user what is still running and end your turn.
Note
An app-enforced limit on how often a helper may be steered is filed on the roadmap for Settings, not built here.

5. Limits the model is told about up front

Ours were only discovered by being refused: 4 at once, one editor, 30 launches, no nesting.

YouCoded today (beta 76)

Task tool description
(none — refusals only: "Refused: this session is at capacity (max 4 concurrent specialists)…", "Refused: another specialist with write access is running…", "Refused: this conversation has reached its specialist budget (30)…")

Claude Code

Docs
Concurrent limit: Default 20 subagents running simultaneously. Nesting depth: 3 levels deep.
Workflow tool
keep workflows under 15 agents… the user must request that scale

Codex CLI

Per-turn prompt section
There are {N} available concurrency slots, meaning that up to {N} agents can be active at once, including you.
Depth refusal
Agent depth limit reached. Solve the task yourself.

Hermes Agent

delegate_task tasks field
The task(s), up to {max_children} in parallel for this user (set via delegation.max_concurrent_children).
delegate_task
Children cannot call delegate_task, clarify, memory, or cronjob.

Pi

Official extension
MAX_PARALLEL_TASKS = 8, MAX_CONCURRENCY = 4 (in code; the model sees only the error "Max is 8")

YouCoded proposed (on this branch)

Task tool description
Limits: up to 4 specialists run at once (fewer on a local engine), only one of them may edit files, specialists cannot start specialists, and each conversation has a budget of 30 launches. Independent read-only specialists can be started in the same turn.
Note
Making these adjustable in Settings is filed on the roadmap.

6. How each helper is described to the model

Ours said what a helper HAS. Claude Code's field is literally "when Claude should delegate to this subagent".

Fast, read-only codebase search — locates files, symbols, and patterns.
researcher
Web research with sourced, cited findings.
reviewer
Read-only code review — findings reported as file:line.

Focused implementation — edits code and runs the relevant tests.

Explore agent
Read-only search agent for broad fan-out searches — when answering means sweeping many files, directories, or naming conventions and you only need the conclusion, not the file dumps. It reads excerpts rather than whole files, so it locates code; it doesn't review or audit it.
Custom agents
description: When Claude should delegate to this subagent

Use explorer for specific codebase questions. Explorers are fast and authoritative… you should trust the explorer results without additional verification… spawn up multiple explorers in parallel when you have multiple distinct questions… Reuse existing explorers for related questions.
worker role
Explicitly assign ownership of the task (files / responsibility)… Always tell workers they are not alone in the codebase…

Hermes Agent

(no roster)
One generic child that inherits the parent's tools.

Pi

(descriptions never shown to the model)
Agent .md files carry name/description, but the parent only sees names in an error: "Unknown agent: … Available agents: …"

YouCoded proposed (on this branch)

explorer
Use when the answer needs a sweep of many files and you only want the conclusion — never for one symbol or file you already know.
researcher
Use for outside facts that need sources and citations — not for something one WebSearch would answer.
reviewer
Use for a fresh-eyes check of a change before you call it done; findings come back as file:line. It cannot run tests.
worker
Use for one bounded change you have already scoped and are not blocked on; it edits code and runs the relevant tests. You stay responsible for checking its report.

7. What the model reads when a helper's report lands

Ours arrives as a full new turn with no instruction about whether to speak. Hermes tells the model it may have moved on. Codex does not start a turn at all.

YouCoded today (beta 76)

Delivered report (starts a new turn)
[Background specialist finished] {name} ({type}) completed the task you delegated ("{description}", started {N}m ago, {steps} steps).

## Report from {name} …
Failure
[Background specialist failed] {name} ({type}): {reason}. Partial transcript: specialist session {id}.

Claude Code

Task notification (starts a new turn)
<task-notification> … <status>completed</status> <summary>Agent "…" finished</summary> <result>…</result>
Agent tool description
The agent's final report is not shown to the user — relay what matters.

Codex CLI

Mailbox (does NOT start a turn)
Message Type: FINAL_ANSWER … read automatically at the start of the parent's next turn, or between thoughts mid-turn. Nothing in the mailbox starts a turn unless sent with trigger_turn, which cannot target the root agent.

Hermes Agent

Completion message (starts a new turn)
[ASYNC DELEGATION COMPLETE — {id}] A background subagent you dispatched earlier has finished. You may have moved on since dispatching it; the full task source is below so you can act on the result or re-dispatch if things have changed.
delegate_task
Child summaries are SELF-REPORTS, not verified facts: a child claiming "uploaded successfully" or "file written" may be wrong… verify it yourself before telling the user the operation succeeded.

Pi

Official extension
The report is the tool result (foreground).
tintinweb extension (starts a new turn)
<task-notification> … <summary>Agent "…" completed</summary> <result>(500-char preview; use get_subagent_result for full output)</result>

YouCoded proposed (on this branch)

Built on this branch
After you press Stop, reports are held and spliced in quietly ahead of your next message — no turn of their own. After a normal answer a report still starts a turn (unchanged).
Proposed wording, not applied — your call
[Background specialist finished] … The user may have moved on or stopped you since you delegated this. If the report still matters to what they asked, act on it or summarise it in a few lines; if it no longer matters, say so in one sentence and stop.

8. How the model knows what is still running

Your question. YouCoded is the only one that hands the model a fresh "still running" list every turn; the others make it remember or ask.

YouCoded today (beta 76)

<specialists-status> block (every turn, only while something is outstanding, rebuilt from disk)
{name} ({type}): running — {N}s[, may be stuck — no activity for at least 2m]
{name} ({type}): finished — report delivery pending
{name} ({type}): failed — {reason} — report delivery pending
{name} ({type}): interrupted — no report will arrive
Background commands
Not in the block. Bash launch reply: "Started in the background (shell id …). You'll be told when it finishes. BashOutput reads new output (or lists runs); KillShell stops it. Running now: N of M." BashOutput without an id lists them; "Do NOT use to continuously poll — read it a few times per turn at most."
After a context summary
The block is rebuilt from the helper ledger every turn, so the fact that helpers are running survives; the summary prompt never mentions helpers, so the model's own notes about them may not.

Claude Code

Per-turn list
None observed. The launch reply says "You will be notified automatically when it completes… if the user asks before it arrives, say it's still running." TaskStop and Monitor tools exist; /tasks is for the human.

Codex CLI

Per-turn prompt
Only the cap: "There are {N} available concurrency slots… including you." No running list.
Tools
list_agents → names + status (running / completed / errored…). wait_agent: "Wait for a mailbox update from any live agent… prefer longer waits (minutes) to avoid busy polling."
After a context summary
Descendant messages and final answers are dropped from the summary; undelivered mail survives in the queue.

Hermes Agent

Per-turn list
None. The model relies on its own dispatch note and delegate_task(action='list') → live children with id, goal, status, running_seconds, live_transcript.
After a context summary
Not preserved; the completion message is self-contained so the parent can act on it cold. ("You may have moved on since dispatching it; the full task source is below.")

Pi

Official extension
Foreground only — nothing runs between turns.
Community extensions
tintinweb: get_subagent_result (with wait) — "do NOT sleep, poll, or proactively check". nicobailon: subagent({action:"status"}) and, after a context summary with live jobs, a hidden nudge: "Compaction is complete. Resume the parent task now; background subagent results will arrive separately when ready."

YouCoded proposed (on this branch)

Kept as is
The per-turn status block stays; it is what lets the assistant answer "is the researcher done?" without guessing.
Two holes worth closing later (not built)
Background commands could join the same block instead of needing a BashOutput listing. An interrupted helper's "no report will arrive" line appears to stay in the block for the rest of the conversation.

9. What Stop does to running helpers

Background: after you press Stop, our app used to deliver a finished report immediately as a new turn. That is what this branch changes.

YouCoded today (beta 76)

Before this branch
Stop halts the answer and any foreground helper; background helpers and commands keep running, and their reports started a new turn the moment they landed — Stop was exactly the idle moment the delivery was waiting for.

Claude Code

Docs
Silent on Esc. Runtime: background agents keep running; a completion notification wakes the session.

Codex CLI

Esc
Aborts the parent only; children keep running. The model then sees "The user interrupted the previous turn on purpose…". Late results wait in the mailbox and do not start a turn.

Hermes Agent

Ctrl+C
Does not cancel children (only /stop does). A completion drains whenever the agent is idle, so it CAN start a fresh turn after Ctrl+C.

Pi

Esc
Kills the child processes ("Subagent was aborted"); nothing outlives the turn.

YouCoded proposed (on this branch)

On this branch
Stop sets a hold. Finished reports and background-command notices stay parked until your next message, then are spliced in quietly ahead of it as context. Three tests pin it. Background helpers still keep running (unchanged).
Not verified from public docs: Claude Code's behaviour after Esc. Hermes's Ctrl+C behaviour and Codex's mailbox mechanics come from their source code, not their docs.
