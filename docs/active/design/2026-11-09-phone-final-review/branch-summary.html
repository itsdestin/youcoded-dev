What the phone branch changes

Card #213, branch session/android-ux-test in the app and the server. Written 10 Nov 2026. Nothing is merged.

1. Your decisions (10 Nov)

  • Start mode: "auto is fine as built". New and resumed sessions start in auto on the phone and the computer, unless Skip permissions is on, or you or the folder set a default mode. Two cases remain untested: a computer with an old Claude Code that does not know auto, and an account that has never accepted Claude's "Enable auto mode?" question.
  • Attachments: kept seven days, then cleaned up.
  • Arrow buttons: left as they are for now. They stay phone-layout only and still cover the right end of Claude Code's input line.

2. Phone app

Starting up

  • The crash on first start is fixed, and if the engine ever fails to start you get a plain screen with Try again and a bug report that lists exactly what it will send.
  • New loading screens in the app's own style. The first launch after this update takes a little longer once (roughly ten seconds, by the reviewer's estimate), while files are laid out again; later updates are faster than before.
  • Claude's first-run questions (theme, sign-in choice, security notes, folder trust) appear as cards in the chat. A new or reworded question from Claude still gets buttons where the app can read it safely; if it cannot, the loading screen says "Claude Code is asking something" with a button to open the terminal. It never switches to the terminal by itself.
  • Sign-ins that send you to the web browser bring you back to YouCoded when they finish: Claude, ChatGPT, your YouCoded account, OpenRouter and GitHub. Not covered typing /login inside a running session.

Typing and the keyboard

  • The page no longer squashes and redraws when the keyboard opens. The message box, the newest messages and the frame's edge glide up together, and a popup's own text field no longer drags the chat with it.
  • The keyboard-height overshoot on your Flip is corrected and remembered.

Terminal view

  • Claude Code no longer prints its banner or replies twice. The session starts at the size it will keep, and the keyboard or a taller message box slides the terminal instead of resizing it.
  • Claude Code runs in its fullscreen display on the phone, and a swipe scrolls it. A one-time tip explains this and how to switch back (/tui default).
  • A key row (Ctrl, Esc, Tab, Enter, Space, arrows) styled like the quick chips. Files and games open in terminal view instead of a black screen. The terminal starts below the header.
  • One green scroll bar, visible inside the frame.

Chat and screens

  • Tighter spacing and taller tap targets. No chat scroll bar. Message times show only where they help; tap a message to see its time.
  • Popups fit and centre on the screen. Settings opens without a "Loading" flash. Pages and Resume show one pane at a time, including on the Flip's wide inner screen.
  • The permission badge shows the right mode from the first second.
  • The skills drawer slides smoothly while dragged.
  • The "Home" project is gone from folder lists; a session with no folder opens in an empty one. Older sessions that were filed under Home still appear in Resume and All sessions (the list is built from every saved conversation, not from the folder list); they are just no longer grouped under a Home project. Nothing is deleted.
  • Backup and sync shows the phone's real name instead of "localhost", sizes in MB/GB, and device rows that fit.
  • Attachments keep their real names, there is a size limit with a clear message, and copies are cleaned up after seven days.
  • Games: two-player rooms work again (after the server is merged). Solo games were unaffected.
  • "Needs you" alerts: on a locked phone they now say only "A session needs you"; the detail shows after unlocking.

3. Computer app

Terminal view looks and sizes exactly as in the released app; the pictures match apart from the scroll bar.

What you may notice

  • Start mode: new and resumed sessions start in AUTO (see section 1).
  • Terminal: the grey second scroll bar is gone; only the green one shows. It cannot be dragged (the grey one could). With a wallpaper theme, the strip above the terminal and under its last row is tinted like the rest of the sheet.
  • Narrow window (under about 640 wide): tighter bubbles, popups sized to fit, taller answer buttons and quick chips, and slightly more left padding in the terminal. The chat scroll bar and message times stay, as you decided ("spacing yes, rest no").
  • Quick chips for new installs read Summarize, Plan my day, Explain this. Existing lists are untouched.
  • Chat titles skip a leading file path.
  • Skills drawer is laid out at full height and slides.
  • Files filter menu closes when the page behind it scrolls. The projects page keeps its scroll fade.
  • About, Terms, Privacy say game rooms run on YouCoded's own server. Your call whether the privacy date should be bumped.
  • Hidden-files tick in the file browser is remembered.

What should not have changed, and how I know

  • A hidden terminal does nothing, as before. A phone fix had briefly reached the computer here; it is phone-only again, with a test.
  • The terminal keeps one size in chat view and terminal view (new test), and a paste into the chat cannot reach a hidden terminal (new test, proved by breaking the guard).
  • The keyboard code does nothing on a computer (tested).
  • Buddy windows keep their normal button sizes.

4. Remote access (a web browser reaching your computer)

  • Laptop with a mouse: terminal view is the computer's terminal. The Buddy row in Settings is hidden there, because a browser cannot float a buddy.
  • Phone or tablet browser: gets the phone's taller buttons, key row, sliding terminal and the terminal starting below the header.
  • Signed-in browsers stop asking for the online-friends list after a few tries (the computer refuses it to browsers; it used to ask forever).

5. Behind the scenes

  • Server (separate branch, merge first): two-player game rooms now run on YouCoded's server. Joining needs a one-time pass that only a signed-in player can get; rooms have message limits, close after 30 idle minutes or 6 hours, and an empty room closes at its first check. Older app versions are no worse off: their games were already broken by the old host shutting down.
  • Daily watch: the check that compares the newest Claude Code's screens with saved copies now includes the first-install screens, and pings your phone when it fails or times out. Needs the alert setting your security watch uses to exist on the app's repository; otherwise it stays silent.
  • Weekly proposal to refresh the phone's bundled parts. Needs the repository setting that lets automation open proposals. If you add a fix to its proposal, next week's run overwrites it.
  • One device rule: "is this a phone, a touch screen, a narrow window?" is now answered in one place, with tests, instead of about fifteen.
  • Keyboard code split into three small parts, with a test written before the split.

6. Independent review

Three fresh reviewers read the whole branch: screens on every device, the phone shell and shared engine, and the menu reader, watch jobs and server.

Found and fixed

  • Narrow computer windows lost the chat scroll bar and message times. Now touch screens only.
  • During startup, a quoted message or a half-typed draft could have been mistaken for a menu and given buttons. The reader now refuses those, with tests using the reviewer's exact screens.
  • A folder's own default permission mode was overridden by "auto". Now respected.
  • A later chat that mentioned "auto mode is unavailable" could flip a correct AUTO badge to NORMAL. Now only believed in a session's first 30 seconds.
  • Lock-screen alerts could show a command. Now hidden until unlock.
  • Buddy windows got taller buttons. Fixed.
  • The computer terminal wrote to storage on every window-drag step. Removed.
  • Browsers on remote access retried the friends list forever. Capped.
  • The phone alert did not fire when a check timed out. Fixed.
  • An abandoned game room lingered for 6 hours. Fixed.
  • A small leak each time the phone restarted its engine. Fixed.
  • The "Signed in" alert also showed after a failed sign-in. Reworded "Back to YouCoded".

Found and left, with reasons

  • Older Home sessions on the phone no longer sit under a project row. They still show in Resume and All sessions (confirmed by reading how that list is built, not on a phone).
  • A stray local web request could bring the app forward once while a YouCoded account sign-in is open, and use up the real return. It needs a lucky guess of a hidden number; low risk, no data exposed.
  • Scrolling a very long chat on the computer may be slightly less smooth from a fix made for the phone. Not measured.
  • A phone build can fail on the day a bundled part is republished upstream, until the weekly refresh runs. It blocks a release rather than shipping a wrong one.
  • One network with many players (a classroom) could hit the room-pass limit of 20 a minute and see "wait a minute".
  • The phone's arrow buttons can sit in the wrong place after a session switch until the next redraw.

  • Phone shell: 55 unit tests pass. No phone build was made from the final state.
  • Server: 505 tests pass. One of them failed once while the machine was busy with the big suite and passed on every run since; I could not make it fail again to find the cause.
  • Pictures of every named screen open, and the saved click-paths pass.

Not checked on a real device since your last phone test: everything from 9 Nov onward. That includes the keyboard after its tidy, the laptop-browser terminal, the scroll bar, the sign-in returns, the fullscreen tip, the new first-run buttons and the lock-screen alert.
