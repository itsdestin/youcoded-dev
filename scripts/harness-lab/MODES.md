## Password-free external-behavior v2 (offline only)

`comparison-external-v2.json` explicitly supersedes **only for new, explicitly selected v2 tasks** the unobservable v1 input-purity, lock-count and concurrent-execution assertions. V1 `comparison-contracts.json`, historical freezes and their unverified verdict remain unchanged. `comparison_tasks.reset(..., contract_version='substantial-development-external-v2')` includes the delta in TASK.md. The submission API requires **both** `backend='bwrap'` and that exact `contract_version`, plus an explicit `BwrapExecutor`. No backend fallback, Docker invocation or privilege escalation occurs.

The trusted Python controller in `external_verification.py` grades public functional outputs against its own cases and reads persisted state after sandbox exit. `external-invocation.cjs` is a public untrusted API driver, not a source of trusted observations. It invokes the real parser, publisher, download verifier, migration helper, store and cloud resolver. The controller launches signing/batch/planner CLIs and regression tests directly in separate sandboxes; it observes their actual exit codes and actual output files. Tests must also fail on a separate original-defect copy, but cannot replace the independent host checks. Store v2 acceptance enforces sequential persisted/API behavior, not internal scheduling or in-memory mutation facts. Read-only input/source mounts enforce persisted input preservation. Correct-looking frames cannot hide a corrupted persisted config or installer.

`bwrap_executor.py` uses user/mount/PID/network/IPC isolation, capability drop, disabled nested user namespaces, cleared environment, read-only root/source/adapter/inputs and isolated proc. No controller oracle, home, credentials or host socket is mounted. Small writable tmpfs scratch and a disposable output mount are exposed. Linux x86-64 seccomp denies fork/vfork/non-thread clone/clone3; Node threads remain in the same bounded address space. Resource limits cover CPU, 16 GiB virtual address space (Node's code reservation), 2 GiB writable data, 128 MiB Node old heap, 64 descriptors, 2 MiB/file, 8 MiB scratch, 256 KiB combined stdout/stderr, and per-call wall deadlines. Output count (32) and aggregate bytes (2 MiB) are descriptor-safe monitored rejection/kill bounds, **not filesystem quotas**. No kernel-escape claim. Unsupported runtime capabilities fail closed. Cleanup signals only each newly owned invocation group.

Actual offline controls live in `test_external_verification.py`: references/alternatives, unchanged and all existing negative mutations, forged valid frames with actual persisted corruption, early exits, stdlib tampering, home/socket/network/proc/source isolation, spawn denial, timeout, memory/output/file/tmpfs bounds and oversized-input preflight. These qualify neither general shell capability nor any paid matrix. **ALL execution admission and Harbor reward/extraction holds below remain active.** No caller may turn a v2 offline reward into a Harbor reward or execution credential.

## Named workflow

`python3 -B scripts/harness-lab/evaluation_workflow.py --help` lists:

- `plan --request REQUEST.json --out NEW_PLAN`: exact mode/arm/task matrix and fingerprints; no key loading/network/spending.
- `prepare --plan PLAN/plan.json --settings SETTINGS.json --out NEW_BUNDLE`: rechecks current source/plan/builds, freezes copies, exports tasks, distinct opaque per-trial gateway grants, explicit limits, scoped budget and unapproved authorization template.
- `check --manifest BUNDLE/prepared-manifest.json`: verifies exact matrix, paths, build/task/source hashes, image pin, limits, grants and existing shared-ledger metadata.
- `run --manifest ... --dry-out NEW_COMMANDS.json`: checks the bundle and exports **actual serial-runner/adapter commands**, no subprocess orchestration/provider calls.
- `qualify --manifest ... --out NEW_RECEIPT.json`: current, whole-selected-matrix **no-provider** checks; no keys, gateway, installs or pulls. Emits each arm/build/lock/image/task/cell verdict, actual reference/negative checks and lifecycle blockers. Exit 0 means qualified; 2 means explicit not-qualified. The receipt is hash-bound evidence, not a reusable execution credential.
- `run --manifest ... --execute --authorization EXACT_RECEIPT.json --key-file PRIVATE_KEY_FILE`: universally refuses new execution **before** token/key/ledger/gateway/runner access while independent observations and authority/lifecycle remain unqualified. This includes direct serial/parallel calls and schema-1 historical replays. No schema downgrade or caller receipt can bypass it. Historical evidence and all selected cells remain intact.
- `report --manifest ... --out NEW_REPORT`: primary **full evidence report** in `report.md` and `summary.json`, using the parent's reviewed loader/renderer and all 13 metric families. Actual adapter identities, arm pairs, splits, unstarted/unsupported/synthetic labels and missing values are preserved. Reads original frozen hashes/plan/journals/ledger; no current planner execution or runtime qualification is required. `inventory.json`/`inventory.md` remain supplemental compatibility files, not replacements for the full report.
- `fixture --out NEW_FIXTURE`: retains a complete no-provider compare plan/preparation/check/command inventory/report and three independently checked references. Fake build/image are explicitly blocked from paid execution. It uses a private dummy ledger and never reads the real ledger or provider key.

Request fields (strict, no unknown keys): `mode`, `profile`, `arms`, optional `taskIds` (basic selection only; compare may spell the exact fixed cohort), exact panel `model`, explicit `provider`, `network`, `limits`, `budgetUsd`, digest-pinned `image`.

Each arm: `{id, adapter, version, fingerprint, desktopDir? , capabilities?}`. Native version is `build:<fingerprint>`; fingerprint is the actual `snapshotDesktop()` digest of dist/package/launcher inputs, and `desktopDir` is explicit. Basic IDs are `baseline`/`candidate`. Competitor fingerprint equals the immutable image digest, with exact registry version checked separately at adapter install-check time. This is an image pin, not a separately measured executable hash. Omitted capabilities mean the registry's implemented filesystem/shell/verifier/controlled-CLI retrieval capability set; explicit omissions block corresponding cells. Registry parity with the existing supported runner adapters is tested.

Settings fields (all required): absolute `harbor`, existing private `sharedLedgerPath`, `gatePolicy` (same documented strict fields/reservation bounds as targeted workflow), positive `stopMarginUsd` below experiment cap. The shared cap must remain at most USD15. Every trial has an additional experiment-wide gateway budget scope, not a new independent allowance. Missing/closed/changed ledgers refuse. Plans are not approval receipts.
